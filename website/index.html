01 // THE ADVANTAGE

The language goes where the data lives.

Instead of moving logic into another service or exposing an entire host, embed Hara and grant a script only the operations it needs.

01

Fast kernel

Native and WASM execution share the same language and collection semantics, with performance work measured against established Lisp runtimes.

02

Safe values

Persistent vectors, maps, sets, queues, ordered collections, sorted collections, and tries use structural sharing and deterministic hashing.

03

Explicit interop

Files, sockets, processes, WASM exports, database calls, and host objects are visible capabilities—not ambient language escape hatches.

03 // WASM INTEROP

Use WASM like a library.

Require an extension namespace and call its generated Vars. Hara validates the manifest, selects an ABI, checks capabilities, owns opaque handles, and settles asynchronous results.

  • core.v1 for direct scalar exports
  • hta.v1 for stateful async modules
  • Import-free modules and explicit host calls

04 // DATABASE SCRIPTING

Write the logic once.

Redis and PostgreSQL are the first database hosts: one executes Hara in an embedded kernel; the other receives procedural source from Tahto.

rate_limit.halREDIS SCRIPT
(ns scripts.rate-limit
  (:require [redis.script :as redis]))

(defn allow? [key limit]
  (let [count (redis/call "INCR" key)]
    (when (= count 1)
      (redis/call "EXPIRE" key 60))
    (<= count limit)))

05 // TAHTO

Programs are data. Targets are models.

Tahto is Hara's grammar-driven transpiler. JavaScript and Python emission are tested today; PL/pgSQL extends the same versioned model.

input.halHAL
(defn add [x y]
  (return (+ x y)))
output.jsJAVASCRIPT
function add(x,y){
  return x + y;
}
output.pyPYTHON
def add(x,y):
  return x + y
